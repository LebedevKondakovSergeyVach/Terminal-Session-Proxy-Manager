# Workflow & Rules for AI Agents

**ВНИМАНИЕ АГЕНТАМ! (ATTENTION AGENTS!)**
При работе с данным проектом строго соблюдайте следующие правила рабочего процесса.

## 1. Локальные тесты (Local CI/CD)
Любое изменение в бизнес-логике или конфигурации может сломать unit-тесты (особенно тесты в `src/config/app.rs`, проверяющие парсинг или значения по умолчанию). 
**Обязательное правило:** Перед созданием коммита вы обязаны запустить:
```bash
cargo check
cargo test
```
Если тесты падают, исправьте их перед тем как пушить!

## 2. Обновление графики и README
Проект содержит скриншоты терминального интерфейса (например, дашборд TUI).
Если вы вносите серьезные изменения в UI (файлы, связанные с `ratatui` или логгированием), вам нужно спросить пользователя, нужно ли обновить скриншоты в `assets/`.
Если скриншот обновляется, чтобы обойти кэш картинок GitHub (`Camo`), файл следует переименовывать (например, `assets/dashboard_v2.png`) и обновлять ссылки в `README.md` и `README.ru.md`.

## 3. CI/CD Релизы
Проект настроен на автоматическую публикацию релизов через GitHub Actions (`.github/workflows/release.yml`).
Триггер срабатывает при пуше тега с префиксом `v` (например, `v2.1.1`).
**Как выпустить релиз:**
1. Поднимите версию в `Cargo.toml`.
2. Запустите `cargo check`, чтобы обновился `Cargo.lock`.
3. Закоммитьте изменения: `git commit -am "chore: bump version to X.Y.Z"`.
4. Создайте тег: `git tag vX.Y.Z`.
5. Отправьте тег: `git push origin main --tags`.

*(GitHub Actions автоматически соберет бинари и обновит brew формулу в `homebrew-tap`)*

## 4. Поддержка языков (Localization)
При добавлении новых команд CLI или текстовых выводов:
- Текст командной строки (`src/cli.rs` -> `///`) должен быть двуязычным (`Английский | Русский`).
- Все строки, которые выводятся пользователю в консоль, должны быть добавлены как новые ключи в `locales/ru.json` и `locales/en.json` и вызываться через `i18n.t("key")`. **Никакого хардкода строк в исходниках!**

## 5. Документация
Всегда обновляйте `README.md` (английская версия) и `README.ru.md` (русская версия) синхронно. Если добавляется новая команда (например, бенчмарк), она должна быть задокументирована в обоих файлах.
