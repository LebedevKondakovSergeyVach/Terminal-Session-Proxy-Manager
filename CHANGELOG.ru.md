# История изменений (Changelog)

Все важные изменения в этом проекте документируются в данном файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), и
проект следует [семантическому версионированию](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [2.3.0] — 2026-09-08

Релиз про документацию. У проекта появился опубликованный сайт, а вывод CLI
переработан для терминалов и скриптов, которым оформление только мешает. Два
изменения затрагивают скрипты — см. раздел **Изменено**.

### Добавлено

- **Docs**: Сайт документации, опубликованный по адресу
  [lebedevkondakovsergeyvach.github.io/Terminal-Session-Proxy-Manager](https://lebedevkondakovsergeyvach.github.io/Terminal-Session-Proxy-Manager/ru/),
  на русском и английском. Страницы генерируются из собственного Markdown
  репозитория, поэтому сайт и файлы на GitHub не могут разойтись.
  Полнотекстовый поиск, вкладки в инструкциях по установке, пошаговые
  руководства и цветные блоки-подсказки, плюс `llms.txt` для машинного чтения.
- **Docs**: `CHANGELOG.ru.md` — история изменений на русском, публикуется по
  `/ru/changelog/`. `README.ru.md` теперь ведёт на неё, а не на английский файл.
- **Docs**: Собственная страница 404 на обоих языках.
- **Docs**: В `docs/SHELL_INTEGRATION.md` появилось объяснение, *зачем* нужна
  shell-функция, с диаграммой последовательности; `docs/USAGE.md` начинается с
  разбивки подкоманд на четыре категории.
- **Docs**: Интерфейс поиска переведён на русский — через коллекцию переводов
  `pagefind.*` в Starlight.
- **CI**: `website.yml` проверяет каждый pull request, затрагивающий сайт или
  документы, из которых он собирается: запускает тесты генератора, собирает
  сайт и падает на битой внутренней ссылке. `pages.yml` публикует из `main`.
- **CI**: Dependabot теперь следит и за npm-зависимостями сайта, а не только
  за Cargo и GitHub Actions.
- **Config**: OpenAI и Anthropic добавлены в стандартный список `ping_targets`.
- **CLI**: `proxy switch` показывает статус `[ON]` / `[OFF]` у каждого профиля
  и убирает меню с экрана при закрытии — и после выбора, и после отмены.
- **CLI**: `proxy ping` печатает ответы HTTP 2XX зелёным, остальные — жёлтым.

### Изменено

- **CLI**: `proxy on` и `proxy off` больше не печатают строку подтверждения.
  Выводятся только shell-выражения для `eval`, поэтому
  `eval "$(proxy env on)"` теперь молчит. **Скрипт, разбиравший это
  подтверждение, нужно поправить.**
- **CLI**: Эмодзи убраны из строк локализации и из заголовков отчётных команд —
  `ping`, `diagnose`, `monitor`, `git`, `import`, `benchmark`, `speedtest` — и
  из индикатора порта в дашборде. У маркера приглашения и у заголовка дашборда
  они остались. Статусы, которые печатает `proxy ping`, теперь переводятся, а
  не зашиты по-английски.
- **CLI**: Разделитель между блоками отчёта — обычная линия вместо жирной
  голубой.
- **Docs**: `docs/*.md` и `CONTRIBUTING.md` — обычный CommonMark. Вкладки,
  карточки, шаги и подсказки сайта записаны комментариями `<!--site:…-->`:
  GitHub их не показывает, а генератор сайта разворачивает — один и тот же файл
  корректно читается в обоих местах. Промежуточная версия этого релиза вставляла
  компоненты прямо в документы, из-за чего на GitHub у них пропадали заголовки.
- **Docs**: В `docs/CONFIGURATION.md` приведён полный список `ping_targets`
  по умолчанию.
- **CLI**: `proxy use <key>` печатает тот же тег `[ON]` / `[OFF]`, что и
  `proxy switch`, — то есть форма выводимой строки изменилась.
- **Contributing**: изменение в `docs/`, README, `CONTRIBUTING.md` или
  changelog теперь должно проходить и сборку сайта
  (`cd website && npm ci && npm test && npm run build`), потому что эти файлы —
  содержимое сайта.

### Удалено

- **CLI**: Ключи перевода `env_on_msg` и `env_off_msg` — не используются с тех
  пор, как `proxy on` и `proxy off` перестали печатать подтверждение.

## [2.2.0] — 2026-08-20

Релиз, направленный на повышение надежности и корректности работы. Исправлен ряд давних ошибок, включая ту, которая могла привести к потере сохраненных профилей пользователя, а также уязвимость с shell-инъекцией. Два изменения влияют на скрипты — см. раздел **Изменено**.

### Исправлено

- **Некорректный `config.json` больше не удаляет ваши профили.** Первая попытка исправления была неполной и была выявлена в ходе ревью: функция `load()` перестала перезаписывать файл, однако следующая команда, выполняющая сохранение (`profile set/use/remove`, `import` или нажатие Enter в дашборде), по-прежнему записывала дефолтные значения прямо поверх него. Теперь некорректно спарсенный конфигурационный файл помечается соответствующим образом, а любая попытка сохранить изменения поверх него завершается ошибкой с пояснением. Команды только для чтения продолжают работать, что позволяет диагностировать проблему с файлом. То же самое относится и к `settings.json`, где перезапись также неявно сбрасывала `config_path` и перенаправляла утилиту на другой файл конфигурации.
- **`env on` возвращает ненулевой код завершения при отсутствии активного профиля.** Ранее выводилось сообщение об ошибке, но код возврата был `0`, из-за чего цепочка `proxy_on && deploy` продолжала выполняться в терминале без прокси.
- **`profile set` больше не сбрасывает протокол существующего профиля.** Для флага `--protocol` было задано значение по умолчанию, из-за чего изменение только порта неявно перезаписывало протокол `http`-профиля на `socks5`.
- **IPv6-профили теперь генерируют валидные URL.** Запись вида `::1` принималась, но преобразовывалась в `http://::1:1080`, что не может разобрать ни один клиент. Теперь литералы заключаются в квадратные скобки в URL и остаются без скобок в параметрах JVM `-Dhttp.proxyHost=`, в соответствии с требованиями каждого из форматов.
- **Ошибка применения URL прокси больше не расценивается как успех.** Ошибка создания прокси игнорировалась, из-за чего запрос отправлялся *напрямую*: `monitor` сообщал о неработающем туннеле как об исправном, `benchmark` помещал неработающий профиль на первое место по скорости, после чего `best` выбирал его, а `status` и дашборд отображали реальный IP-адрес машины так, будто это IP прокси.
- **Дашборд больше не искажает собственное отображение.** Нажатие `s` запускало бенчмарк, чей спиннер прогресса выводит данные в stderr по таймеру, перекрываясь с кадрами ratatui.
- **Выбор в дашборде больше не сбивается при поступлении результатов бенчмарка.** Список сортировался заново без пересчета положения курсора, из-за чего нажатие Enter применяло тот профиль, который случайно оказался под курсором.
- **Shell-обёртка возвращает реальный статус завершения.** Шаг повторного применения настроек становился собственным статусом функции и инвертировал его: `proxy use work` возвращал ошибку при успехе при выключенном прокси, а `proxy use nope` возвращал успех при ошибке при включенном.
- **`run` больше не позволяет дочерней команде переопределять настройки самого менеджера.** Предварительный парсер сканировал всю командную строку, поэтому `proxy run mytool --lang en` изменял конфигурационный файл, загружаемый самим менеджером.
- **`speedtest` сообщает об обрыве соединения вместо некорректно рассчитанной скорости.** Ошибка передачи данных посреди потока была неотличима от штатного завершения тела ответа.
- **`diagnose` разрешает доменные имена (DNS).** Проверка сокетов принимала только IP-литералы, поэтому профиль с доменным именем всегда отображался с закрытым портом. Функция `load()` перезаписывала нечитаемый конфиг дефолтными значениями, поэтому одна случайная запятая приводила к незаметному удалению всех профилей. Файл, который существует, но не может быть спарсен, теперь выводится в stderr и сохраняется байт-в-байт. То же самое относится к `settings.json`.
- **`proxy --help` больше не выводит необработанный ключ `cmd_debug`.** Для подкоманды `debug` отсутствовал перевод. Теперь тест проверяет наличие описания для каждой подкоманды на обоих языках.
- **`proxy run` корректно принимает флаги для дочерней команды.** Вызов `proxy run curl -sS URL` завершался ошибкой «unexpected argument '-s'»; теперь аргументы после имени программы передаются без изменений.
- **Флаг `-h` снова везде означает `--help`.** В команде `profile set` он был привязан к `--host`, перекрывая флаг вызова справки для этой подкоманды.
- **Дашборд больше не паникует при пустом списке профилей.** Нажатие клавиши со стрелкой вычисляло `len() - 1` для пустого списка, что вызывало панику на альтернативном экране и оставляло терминал в неработоспособном состоянии.
- **Терминал корректно восстанавливается при любом выходе из дашборда.** RAII-гард в сочетании с перехватчиком паник (panic hook) заменили прежнюю очистку, работавшую только при успешном завершении, из-за чего пользователи оставались в raw-режиме на альтернативном экране при любой ошибке или панике.
- **Дашборд экспортирует те же переменные, что и `env on`.** Ранее он устанавливал только `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY`, опуская имена в нижнем регистре и параметры для JVM.
- **Импорт постороннего JSON-файла больше не создаёт фиктивные профили.** Поскольку каждое поле конфигурации имеет значение по умолчанию в serde, любой JSON-объект успешно парсился и «импортировал» два встроенных профиля по умолчанию.
- **`git on` / `git off` сообщают об ошибках.** Статус завершения команды `git config` игнорировался, поэтому при отсутствии установленного `git` всё равно выводилось сообщение об успешном выполнении.
- **`monitor` больше не считает статус 404 успешным.** Теперь он опрашивает настраиваемый `health_check_url`, возвращающий `204`, вместо специальной обработки ошибочного ответа конкретного API.
- Результаты бенчмарка теперь отличают недоступный прокси от просто медленного; ранее специальное значение-маркер `9999` объединяло оба случая.
- Переменная `NO_COLOR` обрабатывается в соответствии со спецификацией (любое непустое значение), а не только при ее наличии в окружении.

### Безопасность

- **Shell-инъекция в `env on` и механизме передачи состояния дашборда.** Вывод, передаваемый в `eval "$(...)"`, интерполировал поля профиля без экранирования, что позволяло значению хоста из отредактированного или импортированного конфига выполнять произвольные команды. Теперь все значения экранируются одинарными кавычками POSIX, что подтверждено тестом, выполняющим сгенерированный скрипт в реальном shell.
- Профили проходят валидацию перед сохранением как в `profile set`, так и при импорте: хост проверяется по белому списку символов, порт должен быть ненулевым, а протокол — поддерживаться утилитой.

### Добавлено

- Документированная модель ветвления: `main` <- `release/X.Y.Z` <- task-ветки, описанная в `.ai/GIT_WORKFLOW.md` и контролируемая `.github/workflows/branch-policy.yml`. Pull request'ы проверяются на соответствие именования веток, валидность пары head/base и наличие записи в changelog.
- Автоматическая публикация релизов. Слияние релизной ветки в `main` запускает CI-проверку сборки, создание тега `vX.Y.Z`, сборку бинарных файлов под четыре целевые платформы и обновление Homebrew tap. Создание тегов вручную по-прежнему поддерживается и использует тот же процесс.
- Глобальные флаги `--config-file`, `--settings-file` и `--lang` с соответствующими переменными окружения `TSPM_CONFIG`, `TSPM_SETTINGS` и `TSPM_LANG`. Это обеспечивает возможность автоматизации через скрипты и запуск тестов в полной изоляции.
- Настраиваемые эндпоинты в `config.json`: `ipv4_api`, `ipv6_api`, `health_check_url` и `speedtest_url`, которые ранее были жестко захардкожены.
- Полная локализация для `speedtest`, `monitor`, `git` и TUI-дашборда, которые ранее выводили текст на английском языке независимо от выбранного языка.
- Файлы `CONTRIBUTING.md`, `SECURITY.md`, `AGENTS.md`, `CLAUDE.md`, шаблоны issues и pull requests, а также конфигурация Dependabot.
- Количество тестов выросло с 9 до 126, включая набор сквозных (end-to-end) тестов в `tests/cli.rs`, тестирующий реальный бинарник в изолированной конфигурации.

### Изменено

Два изменения могут повлиять на существующие скрипты:

- **`profile use` и `profile remove` возвращают ненулевой код завершения при передаче неизвестного ключа.** Ранее они выводили ошибку и завершались с кодом `0`, из-за чего конструкция `proxy profile use "$p" || fallback` всегда шла по ветке успешного выполнения.
- **У флага `profile set --host` удалена короткая форма `-h`.** Используйте `--host`.

Также изменено:

- Команда `export` завершается с ошибкой вместо пустого вывода, если нет активного профиля, поэтому `proxy export envfile > .env` не может случайно очистить файл.
- `settings set --lang` отклоняет неизвестный язык вместо автоматического выбора русского.
- Неиспользуемое поле `enabled` удалено из `config.json`. Существующие конфиги продолжают загружаться, поле просто игнорируется.
- `run` в точности транслирует код завершения дочернего процесса.
- Переход на редакцию Edition 2024, MSRV 1.88 и обновление зависимостей: clap 4.6, tokio 1.48, reqwest 0.13, thiserror 2.0, dirs 6.0, colored 3.1, indicatif 0.18, dialoguer 0.12. Директория конфигурации macOS не изменилась при обновлении `dirs`.
- Релизные сборки используют Fat LTO, одну единицу кодогенерации (codegen unit) и очистку отладочных символов (stripped symbols).
- Процесс публикации релиза проставляет тег только после успешной сборки всех бинарных файлов. Ранее создание тега в самом начале приводило к тому, что при сбое сборки создавался тег без опубликованных файлов, а последующие попытки видели существующий тег и навсегда пропускали релиз.
- В CI добавлены проверка MSRV, аудит безопасности `cargo audit`, сборки с флагом `--locked` и проверка сборки документации. Релизы теперь проверяют соответствие тега версии крейта, формируют бинарные файлы для Linux `aarch64` и публикуют контрольные суммы SHA-256.
