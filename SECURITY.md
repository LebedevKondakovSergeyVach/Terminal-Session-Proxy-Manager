# Security Policy

## Supported versions

Fixes land on the latest release. Please upgrade before reporting.

| Version | Supported |
| :--- | :--- |
| 2.3.x | Yes |
| < 2.3 | No |

## Reporting a vulnerability

Please **do not** open a public issue.

Use [GitHub's private vulnerability reporting](https://github.com/LebedevKondakovSergeyVach/Terminal-Session-Proxy-Manager/security/advisories/new),
or email <sergejlebedev31838@gmail.com>.

Please include the version (`terminal-session-proxy-manager --version`), your OS
and shell, what an attacker gains, and the steps to reproduce. You can expect an
acknowledgement within a week, and credit in the release notes unless you would
rather stay anonymous.

## What is in scope

This tool generates shell code that the user's shell evaluates, spawns child
processes, reads configuration written by the user, and can import profiles from
a remote URL. The interesting boundaries are:

- **Shell injection.** The `env on` output and the TUI hand-off file are passed
  to the shell's `eval`. All interpolated values are POSIX single-quoted by
  `proxy_env::shell_quote`, and `Profile::validate` allowlists the characters a
  host may contain before a profile is ever persisted. A way past either layer
  is a vulnerability.
- **Untrusted imports.** `import` accepts a remote URL. Imported profiles are
  validated individually before being saved.
- **Config file handling.** Reading a hostile `config.json` must not lead to
  code execution.

## What is not in scope

- The proxy servers you configure. This tool routes traffic to them; it does not
  vet them, and it cannot protect you from a malicious proxy operator.
- Running the tool with a `config.json` that another local user can write. Its
  contents are trusted to the extent that any file in your home directory is.
- Credentials in a proxy URL you pass on the command line. Those are visible in
  your shell history and process list; that is a property of the shell.
- Reports generated by an automated scanner with no demonstrated impact.

## Note on secrets

`config show`, `status --json` and `export` print your proxy hosts and ports.
Redact anything you consider sensitive before attaching output to an issue.
